# M3 synthesis and creative protocol

M3 transforms three or more independently validated M2 analyses into an original human decision package. It never implements or automatically approves a concept.

## Cross-reference synthesis

Use only `synthesis-packet.json` and the Synthesis Map schema. Do not browse, search, inspect original websites, or open repository files beyond those approved inputs. The restriction is procedural unless the runtime separately removes tools.

Classify every unit as `convergent_pattern`, `complementary_pattern`, `tension_tradeoff`, or `unique_candidate`. A convergent or complementary unit needs at least two distinct references; repeated evidence from one reference is not consensus. Preserve conflicting mechanisms rather than forcing agreement. A unique candidate must remain visibly single-reference and must not claim consensus.

For every unit, reason in this order:

```text
user problem → desired experience → abstract mechanism → tradeoff → original-expression boundary
```

Never assemble a concept as a source-A surface plus source-B navigation plus source-C animation. State why the abstraction helps the Project Brief, when it should not be used, what tensions it introduces, and what source-specific expression must disappear downstream. Cite only valid profile claims and principles through structured reference contributions. Preserve rights and all anti-copy restrictions. Do not treat schema validation as semantic proof.

## Creative concepts

Use only the Creative Packet, Project Brief, Creative Concepts schema, and this section. Do not request or inspect the Synthesis Packet, profiles, principles, URLs, source names, screenshots, evidence, assets, prose, code, geometry, CSS values, or exact source motion descriptions. The Originality Firewall is procedural unless the runtime separately removes tools.

Produce exactly three materially different concepts. They must differ across several meaningful dimensions—such as narrative, interaction, agency, progression, spatial model, pacing, visual metaphor, or technical posture—not merely palette or theme. Technology follows the concept; DOM/CSS, Canvas, lightweight 2D, hybrid approaches, and WebGL are all possible.

Each concept must cite Synthesis Unit IDs only, inherit every protected-expression prohibition, explain its independent-expression rationale, record selected and rejected units, preserve open tradeoffs, and describe a smallest convincing playable slice without production code.

## Independent review

Concept-diversity review asks whether the three directions are materially distinct, grounded in the brief, proportionate in technical assumptions, and honest about mobile/accessibility. Originality review checks for source-pattern leakage, exact-expression risk, source dominance, suspicious specificity, unsupported originality claims, and incomplete rights inheritance. Neither review is legal advice.

Persist both reviews with the `concept-review` schema. Each review must bind the exact concepts artifact SHA-256. A `fail` verdict blocks the gate; `pass_with_warnings` is allowed only when every material warning is carried into the gate package.

The final M3 artifact must remain `pending_human_selection`. Only a future explicit human action may approve, request revision, or reject all concepts.
